# Проверка результатов

Шаг `python run.py validate` проверяет итоговые типы с разных сторон: какие признаки их определяют, как типы лежат на сети, согласны ли с ними другие методы, насколько они устойчивы и как модель выглядит среди всех методов по шести индексам критериев. Шагу нужны результаты `compare`, `track` и `robustness`. Код в `src/validate.py`, параметры в разделе `validate` файла `config.yaml`. Таблицы пишутся в `results/validate_*.csv`, рисунки в `results/figures`. Все проверки идут на окне `compare.period` (скользящий год 2024).

## Признаки

- **Абляция блоков**: модель в одном окне (совместная спектральная кластеризация с параметрами `model`) строится без одного блока признаков, только на потреблении или с рёбрами по всем признакам. Для каждого варианта ARI с моделью на всех блоках. Файл `validate_blocks.csv`.
- **Важность признаков**: случайный лес (Breiman 2001, 400 деревьев) по 25 исходным признакам предсказывает итоговый тип. Точность по 5 фолдам показывает, насколько типы выражаются через исходные признаки, перестановочная важность показывает, какие признаки нужнее всего. Важность занижена у признаков, которые сильно коррелируют с другими. Файл `validate_importance.csv`.

## Сеть

- **Описание графа потребления**: степени, связность, коэффициент кластеризации и средняя длина пути (по 400 случайным стартовым узлам). Для сравнения те же величины на графе, где рёбра перемешаны с сохранением степеней узлов (Maslov, Sneppen 2002), 5 перемешиваний. Индекс малого мира sigma = (C / C_перемешанный) / (L / L_перемешанный) (Humphries, Gurney 2008). Ассортативность по степени. Файл `validate_network.csv`.
- **Смешивание типов**: какая доля веса рёбер МО каждого типа ведёт к МО каждого типа. Доля веса рёбер внутри типов сравнивается с ожидаемой при случайном соединении с теми же суммарными весами узлов, то же для регионов. Файлы `validate_network.csv`, `validate_mixing.csv`.
- **I Морана** (Moran 1950) каждого признака на графе потребления с построчной нормировкой весов, перестановочный тест на 499 перестановках. Показывает, какие признаки согласованы с сетью: у соседей по сети похожие значения. Признаки потребления согласованы с графом по построению, содержательный вопрос в признаках труда и места. Файл `validate_moran.csv`, рисунок `network_structure.png`.

## Мосты между типами

Коэффициент участия (Guimerà, Amaral 2005) P_i = 1 - сумма по типам t (s_it / s_i)^2, где s_it это вес рёбер МО i к МО типа t, s_i это сумма весов его рёбер. P = 0, если все связи МО ведут внутрь его типа, и P растёт, если связи распределены между типами. МО с P больше `validate.bridge_participation` (0.62, порог авторов для узлов-связок) считаются мостами между типами. Для каждого МО записаны тип, P, доля веса рёбер внутри своего типа, главный другой тип и бутстреп-уверенность из шага `robustness`. Файл `validate_bridges.csv`.

## Уверенность и смены типа

Проверка согласованности: отличают ли бутстреп-уверенность в первом окне, коэффициент участия и доля рёбер внутри своего типа те МО, которые сменили тип к последнему окну. Считается AUC и тест Манна-Уитни, а также доля сменивших тип в полосах уверенности. Это не прогноз: многослойная модель строится по всем окнам сразу и видела последнее окно. Файлы `validate_changes.csv`, `validate_changes_by_confidence.csv`.

## Согласие методов

Все методы сравнения строятся с k = `model.k` на одном окне: k-means, Уорд, смесь гауссиан, спектральная по графу, Louvain и Leiden (с первым разрешением, которое даёт k сообществ) и все совместные методы при каждом alpha из `validate.consensus_alphas`, у всех одинаковое число вариантов. К ним добавляются итоговые типы (`multilayer`). Считаются:
- попарный ARI и средний ARI каждого разбиения со всеми остальными; разбиение с наибольшим средним это медоид ансамбля;
- консенсус: спектральная кластеризация матрицы совместной встречаемости, где элемент (i, j) это доля методов, поместивших МО i и j в один кластер (Fred, Jain 2005); итоговые типы в консенсус не входят;
- поддержка методов для каждого МО: средняя доля методов, которые поместили его в один кластер с остальными МО его типа.

Состав ансамбля влияет на консенсус: если в нём много вариантов одного семейства, консенсус тянется к нему, поэтому у каждого совместного метода одинаковое число вариантов. Файлы `validate_methods_ari.csv`, `validate_consensus.csv`, `validate_support.csv`, рисунок `methods_ari.png`.

## Устойчивость

Устойчивость считается как в `compare` (ARI между разбиением всех МО и разбиениями 90% МО), но на `validate.stability_runs` подвыборках, одних и тех же для всех методов и всех k. Для k-means и совместной спектральной кластеризации считается кривая по k из `validate.stability_ks`: k, при котором разбиение воспроизводится лучше соседних, указывает на естественное число групп (Ben-Hur et al. 2002, von Luxburg 2010). Для остальных методов устойчивость считается при k модели в лучшей конфигурации каждого метода по пороговому правилу (см. следующий раздел), чтобы проверить, устойчивы ли лидеры по индексам. Записаны среднее, разброс, 5 и 95 процентили и доля подвыборок с ARI не ниже 0.85. Файл `validate_stability.csv`, рисунок `stability_curve.png`.

## Ранжирование методов по шести индексам

Все конфигурации из `results/methods.csv` с k = `model.k` (каждый метод, а у совместных методов каждое alpha) оцениваются по шести индексам из критериев конкурса: SW, CH, S_Dbw, AVI, AVU, MQ (см. [metrics.md](metrics.md)). По каждому индексу конфигурация получает оценку 1, 2 или 3: лучшая, средняя или худшая треть всех конфигураций. Конфигурации упорядочиваются пороговым правилом (Aleskerov et al. 2007): лучше та, у которой меньше худших оценок, при равенстве та, у которой меньше средних. Правило некомпенсаторное: провал по одному индексу нельзя покрыть рекордом по другому. Для сравнения приводится и компенсаторная сумма рангов по шести индексам (правило Борда), а также доля веса рёбер внутри кластеров и устойчивость из `compare`. Файл `validate_ranking.csv`. В `validate_ranking_methods.csv` лучшая конфигурация каждого метода и её устойчивость на подвыборках этого шага (`stability_runs`): индексы не учитывают устойчивость, поэтому конфигурация может быть лучшей по индексам и при этом плохо воспроизводиться на части МО.
