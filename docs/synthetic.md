# Синтетические данные с известными типами

Внутренние метрики не говорят, насколько разбиение близко к правильному, поэтому методы дополнительно проверяются на синтетических данных, где правильные типы известны. Шаг `python run.py synthetic`, код в `src/synthetic.py`, параметры в разделе `synthetic` файла `config.yaml`. Шагу нужны итоговые типы из `track`.

## Как строятся данные

Синтетические МО собираются из реальных, чтобы данные были похожи на настоящие.
- Центры типов и их размеры берутся из итоговых типов в окне `compare.period`.
- Разброс внутри типа это отклонения реальных МО от центра своего типа. Они раздаются синтетическим МО случайно, без связи с их типом.
- Граф строится так же, как в модели. Это k ближайших соседей по косинусному сходству блока «Потребление» (`network.k`) и граф ближайших соседей по всем признакам.

Сценарии устроены так.
- `calibrated` строится как описано выше.
- В `pairs_by_spending` типы разбиты на пары. Внутри пары блоки «Труд» и «Место» одинаковые, и типы различаются только тратами.
- В `spending_only` блоки «Труд» и «Место» не несут информации о типе.
- В `noisier` разброс внутри типов в `synthetic.noise` раз больше.
- В `independent_graph` разброс в `synthetic.noise` раз больше, а граф не строится из признаков и несёт свой сигнал. Это planted partition с той же средней степенью и долей рёбер внутри типа `synthetic.inside_share`.
- В `no_spending` блок «Потребление» не несёт информации о типе, поэтому граф потребления становится шумом.

Каждый сценарий повторяется `synthetic.repeats` раз с разными seed.

## Что считается

Все методы сравнения строятся с истинным числом типов. Это k-means, Уорд, GMM, спектральная кластеризация по графу, Louvain и Leiden, совместные методы при alpha модели (среди них совместная спектральная кластеризация без уточнения) и модель при каждом alpha из `synthetic.alphas`. Для каждого разбиения считаются ARI с истинными типами и все метрики из [metrics.md](metrics.md).
- `results/synthetic.csv` содержит все разбиения во всех наборах.
- `results/synthetic_ari.csv` содержит средний ARI каждого метода в каждом сценарии.
- `results/synthetic_indices.csv` содержит корреляцию Спирмена каждой метрики с ARI по методам внутри набора, среднюю по наборам. Она показывает, какие метрики в каком режиме выбирают разбиение, близкое к правильному.
- Рисунок `synthetic_ari.png`.

- На данных, похожих на реальные, модель точнее остальных методов в каждом из 5 наборов. У неё ARI 0.69, у k-means 0.59, у KEFRiN 0.60. Шаг уточнения добавляет к совместной спектральной кластеризации 0.05 (без него 0.64), тоже в каждом наборе. Если три пары типов различаются только тратами, разрыв больше, 0.74 против 0.64 у k-means. Лучший вес графа на первом шаге 0.3 и 0.5 (0.69 и 0.68), при alpha 0 получается 0.66, при alpha 1 0.56.
- Если типы различаются только тратами, весь сигнал в графе потребления, и методы по графу лучше (0.44-0.49). Модель находится между ними и методами по признакам (0.41).

- Если граф не связан с типами (`no_spending`), совместные методы почти не находят типы. У модели ARI 0.17, без уточнения 0.04, у методов по признакам 0.38. ## Истинные типы из других методов

В сценариях выше истинные типы взяты из решения модели, поэтому синтетика может давать ей преимущество. Чтобы это проверить, сценарии из `synthetic.truth_scenarios` строятся ещё и на типах других методов, их список в `synthetic.truths`. Для k-means и спектральной кластеризации по графу центры, размеры и разброс типов считаются по их разбиению того же окна, а генератор данных остаётся тем же. На каждом наборе запускаются методы по признакам, спектральная по графу, KEFRiN и совместная спектральная без уточнения при alpha модели и модель при каждом весе графа в уточнении из `validate.refine_weights`. Результаты в `results/synthetic_truths.csv` и `results/synthetic_truths_ari.csv`.

Средний ARI по 5 наборам в сценарии `calibrated`. Столбцы показывают, из чьих типов построены данные, в последнем столбце худший из трёх случаев.

| Метод | типы модели | типы k-means | типы спектральной по графу | худший случай |
|---|---|---|---|---|
| k-means | 0.59 | 0.71 | 0.43 | 0.43 |
| KEFRiN, евклид | 0.60 | **0.72** | 0.47 | 0.47 |
| KEFRiN, косинус | 0.54 | 0.52 | 0.49 | 0.49 |
| GMM | 0.52 | 0.48 | 0.33 | 0.33 |
| Уорд | 0.54 | 0.45 | 0.30 | 0.30 |
| спектральная по графу | 0.46 | 0.31 | **0.62** | 0.31 |
| совместная спектральная без уточнения | 0.64 | 0.45 | 0.51 | 0.45 |
| модель | **0.69** | 0.53 | 0.54 | **0.53** |

То же для сценария `pairs_by_spending`.

| Метод | типы модели | типы k-means | типы спектральной по графу | худший случай |
|---|---|---|---|---|
| k-means | 0.64 | **0.57** | 0.30 | 0.30 |
| KEFRiN, евклид | 0.59 | 0.56 | 0.31 | 0.31 |
| KEFRiN, косинус | 0.56 | 0.54 | 0.44 | 0.44 |
| GMM | 0.46 | 0.48 | 0.28 | 0.28 |
| Уорд | 0.49 | 0.43 | 0.24 | 0.24 |
| спектральная по графу | 0.44 | 0.32 | **0.64** | 0.32 |
| совместная спектральная без уточнения | 0.68 | 0.45 | 0.52 | 0.45 |
| модель | **0.74** | 0.52 | 0.56 | **0.52** |

- Каждый метод лучше всех восстанавливает типы, из которых построены данные. На типах k-means лучше всех k-means и евклидов KEFRiN (0.71 и 0.72), на типах спектральной по графу сама спектральная (0.62), на типах модели модель (0.69).
- Когда данные построены из типов другого метода, модель уступает только этому методу и близким к нему и обгоняет остальные, поэтому её худший случай самый высокий. В `calibrated` он равен 0.53, у следующего метода 0.49, у k-means 0.43. В `pairs_by_spending` 0.52 против 0.45 у следующего метода.
- Значит, модель надёжнее остальных методов, когда неизвестно, какое разбиение ближе к реальности, а на реальных данных это неизвестно всегда. Выигрыш на данных из собственных типов есть у каждого метода, поэтому честнее сравнивать методы по худшему случаю, и по нему модель первая.
- Тот же худший случай помогает выбрать вес графа в уточнении. В `calibrated` он наибольший при w = 0.7 (0.53), в `pairs_by_spending` при w = 0.5 (0.53, при w = 0.7 0.52). Малый вес лучше на типах k-means, большой на типах спектральной по графу.
