# Синтетические данные с известными типами

Внутренние метрики не говорят, насколько разбиение близко к правильному, поэтому методы дополнительно проверяются на синтетических данных, где правильные типы известны. Шаг `python run.py synthetic`, код в `src/synthetic.py`, параметры в разделе `synthetic` файла `config.yaml`. Шагу нужны итоговые типы из `track`.

## Как строятся данные

Синтетические МО собираются из реальных, чтобы данные были похожи на настоящие:
- центры типов и их размеры берутся из итоговых типов в окне `compare.period`;
- разброс внутри типа это отклонения реальных МО от центра своего типа, которые раздаются синтетическим МО случайно, без связи с их типом;
- граф строится так же, как в модели: k ближайших соседей по косинусному сходству блока «Потребление» (`network.k`), и граф ближайших соседей по всем признакам.

Сценарии:
- `calibrated`: как описано выше;
- `pairs_by_spending`: типы разбиты на пары, внутри пары блоки «Труд» и «Место» одинаковые, типы различаются только тратами;
- `spending_only`: блоки «Труд» и «Место» не несут информации о типе;
- `noisier`: разброс внутри типов в `synthetic.noise` раз больше;
- `independent_graph`: разброс в `synthetic.noise` раз больше, а граф не строится из признаков, а несёт свой сигнал: planted partition с той же средней степенью, доля рёбер внутри типа `synthetic.inside_share`;
- `no_spending`: блок «Потребление» не несёт информации о типе, поэтому граф потребления становится шумом.

Каждый сценарий повторяется `synthetic.repeats` раз с разными seed.

## Что считается

Все методы сравнения строятся с истинным числом типов: k-means, Уорд, GMM, спектральная кластеризация по графу, Louvain и Leiden, совместные методы при alpha модели (среди них совместная спектральная кластеризация без уточнения), модель при каждом alpha из `synthetic.alphas`. Для каждого разбиения считаются ARI с истинными типами и все метрики из [metrics.md](metrics.md). Результаты:
- `results/synthetic.csv`: все разбиения, все наборы;
- `results/synthetic_ari.csv`: средний ARI каждого метода в каждом сценарии;
- `results/synthetic_indices.csv`: корреляция Спирмена каждой метрики с ARI по методам внутри набора, средняя по наборам. Показывает, какие метрики выбирают разбиение, близкое к правильному, в каком режиме;
- рисунок `synthetic_ari.png`.

## Результаты

Средний ARI с истинными типами по 5 наборам, совместные методы при alpha 0.3 (alpha модели), KEFRiN и CANUS с евклидовым расстоянием. Модель это совместная спектральная кластеризация с уточнением. SW и MQ истинного разбиения показывают, на что похож сценарий: на реальных данных SW разбиения k-means 0.115, модели 0.124.

| `calibrated` | 0.132 | 0.53 | 0.59 | 0.60 | 0.58 | 0.50 | 0.46 | 0.48 | 0.64 | **0.69** |

| `noisier` | 0.044 | 0.33 | 0.30 | **0.31** | 0.28 | 0.25 | 0.22 | 0.23 | 0.25 | 0.29 |

- На данных, похожих на реальные, модель точнее остальных методов в каждом из 5 наборов: 0.69 против 0.59 у k-means и 0.60 у KEFRiN. Шаг уточнения добавляет к совместной спектральной кластеризации 0.05 (0.64 без него), тоже в каждом наборе. Если три пары типов различаются только тратами, разрыв больше: 0.74 против 0.64 у k-means. Лучший вес графа на первом шаге 0.3 и 0.5 (0.69 и 0.68); при alpha 0 0.66, при alpha 1 0.56.
- Если типы различаются только тратами, весь сигнал в графе потребления, и методы по графу лучше (0.44-0.49); модель между ними и методами по признакам (0.41).
- Если граф несёт сильный собственный сигнал, а признаки шумные, alpha 0.3 для него мал: ARI 0.43, при alpha 0.7 0.63. Уточнение здесь немного мешает (без него 0.46): шаг уточнения смотрит и на признаки, а они в этом сценарии сильно зашумлены.
- Если граф не связан с типами (`no_spending`), совместные методы проваливаются: модель 0.17, без уточнения 0.04, а методы по признакам нет (0.38). Это видно и без истинных типов: MQ разбиения k-means на графе в этом сценарии 0.06, в `calibrated` 0.49, на реальных данных 0.42.
